# Lviv Polytechnic server catalog

A Ukrainian-language community server directory hosted on GitHub Pages. The site uses semantic HTML, compiled Tailwind CSS, and small native JavaScript modules. The Node.js server uses only built-in modules; there are no production npm dependencies.

## Node.js website and comments server

Use Node.js 22.13 or newer (Node.js 24 is recommended):

```sh
npm ci
npm run build
npm start
```

Open http://localhost:3000. `npm start` prepares `dist/` from the committed browser assets and serves both the website and `/api/comments`. Comments and daily posting allowances persist in `data/comments.sqlite`, including after restarting Node. No Cloudflare account, Durable Object, API key, or runtime npm package is required for this hosting mode.

For configuration, copy `.env.example` to `.env`. On Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

| Setting | Default | Purpose |
| --- | --- | --- |
| `PORT` | `3000` | HTTP listening port; hosting providers can supply their own. |
| `HOST` | `0.0.0.0` | Address to bind. |
| `DATA_DIR` | `./data` | Persistent directory for SQLite and its WAL files. |
| `TRUSTED_PROXY_CIDRS` | empty | Comma-separated IPs/CIDRs of the actual reverse proxies. |
| `ALLOWED_ORIGINS` | `https://elon-tuskoff.github.io` | Additional browser origins allowed to call the API; the server's own origin is also allowed. |

For a proxy on the same machine, an example is `TRUSTED_PROXY_CIDRS=127.0.0.1/32,::1/128`. Set only the addresses/ranges of the proxies that actually connect to Node. The proxy must append the real remote address to `X-Forwarded-For`. Node walks the chain from the trusted socket peer to the nearest untrusted address; forwarded headers from direct, untrusted clients are ignored. If Cloudflare and another ingress proxy are both in the chain, configure both trusted ranges appropriately. IPv6 addresses are normalized before hashing.

For public hosting, run one Node service with a persistent volume mounted at `DATA_DIR`, put it behind the host's HTTPS reverse proxy, and keep that SQLite directory across deployments. Multiple instances need the same database file and filesystem locking; independent per-instance disks would create independent comment lists and limits. GitHub Pages and Cloudflare Workers cannot run this standalone Node process. Their existing Cloudflare backend remains available as a separate hosting option; it does not automatically share or transfer its stored comments to Node.

The current frontend uses the same-origin API automatically when Node serves the whole site. To keep the frontend elsewhere and use a separately hosted Node API, set the `comments-api` meta tag in `index.html` to the public HTTPS URL, for example `https://your-node-host.example/api/comments`, and add the frontend's exact origin to `ALLOWED_ORIGINS`. Leave the meta tag empty for the existing hosting behavior. No Node host URL is configured until such a host exists.

## Development

- Edit `index.html` for content, links, availability, and Tailwind utilities.
- Edit `styles/tailwind.css` for theme colors and base accessibility styles.
- Run `npm run watch:css` while changing classes, or `npm run build:css` for a minified stylesheet.
- Edit `index.js` for wallpaper rotation, logo animation, and dropdown interactions.
- Edit `comments.js` for the public comments UI, `server/` for Node hosting, and `worker/` for Cloudflare hosting and the shared repository.
- Run `npm run dev:node` to restart Node automatically after source changes (run `npm run build:static` after editing browser files).
- Run `npm test` for the shared-store, Cloudflare-runtime, Node HTTP/persistence, proxy-IP, and static-file tests.

`index.css` is generated by Tailwind. Do not edit it directly. Commit it with your HTML changes so static hosting can serve the site without a Tailwind CDN script.

## Wallpapers

Keep original PNG/JPEG artwork in `everydayimg/`, then run `npm run build:images`. The script creates WebP copies (up to 1920 × 1080, preserving aspect ratio) in `images/wallpapers/` and updates `wallpapers.js`. Commit both generated outputs. If you remove an original image, remove its generated WebP copy too. If you rename or remove `aboutthat.png`, update the initial image and preload paths in `index.html`.

The first wallpaper displays without JavaScript. With JavaScript enabled, wallpapers rotate every seven seconds after the next image has decoded. Only the next image is preloaded. Rotation pauses in hidden tabs and is disabled when reduced motion is requested. The animated logo loads on hover and also respects reduced motion.

## Server information

Server descriptions and availability are maintained manually in `index.html`. The catalog contains GTNH, Hytale, and Project Zomboid. The Create Modpack card has been removed. There are no status API URLs, API requests, polling timers, player counts, or player-list panels. Visitors can check current availability in Discord. BlueMap is a blue, disabled button without a destination until a link is supplied.

## Public comments

Each server has a public, expandable discussion. `comments.js` loads comments from `/api/comments`, posts form data, displays inline errors and a server-derived posting cooldown, and provides pagination and refresh controls. All names and messages are rendered through `textContent`. Browser-local comments from the previous version are not uploaded or published.

`worker/index.js` handles the API and `worker/store.js` stores comments in a SQLite-backed Cloudflare Durable Object. The Wrangler configuration provisions the `COMMENTS` binding using the `public-comments-v1` migration. No separate database ID, API key, or manual SQL setup is required. Keep the existing migration and class name on future deployments to preserve comments.

A single shared object enforces **one successful comment per IP address across the whole site every rolling 24 hours**. The limit check, comment insertion, and allowance update share one transaction, so parallel requests and switching server discussions cannot bypass it. Invalid submissions do not consume the allowance. A rejected post returns HTTP 429, `Retry-After`, and `nextAllowedAt`.

The Cloudflare backend uses only Cloudflare's `CF-Connecting-IP` header to identify the caller. The Node backend uses the socket address and only the explicitly trusted proxy chain described above. Raw IP addresses are never saved or returned. Rate-limit keys use HMAC-SHA-256 with a randomly generated, private, persistent salt. Expired keys are pruned during successful posts. Public responses contain only comment IDs, names, messages, and timestamps, plus counts, pagination, and the caller's next allowed posting time.

For the Node server use `npm start`; for the Cloudflare development runtime use `npm run dev` instead of a static Python server. `npm test` checks storage and rate-limit behavior; `npm run deploy:check` validates the Worker and static build without publishing. Browser-only static hosting cannot run the API.

## GitHub Pages

Commit `index.html`, `index.js`, `comments.js`, `index.css`, `wallpapers.js`, and the referenced image assets. The generated CSS and images are included in the repository, so GitHub Pages can still serve the static website. On `elon-tuskoff.github.io`, comments connect to the existing production API at `https://elon-tuskoff-github-io.gandrij549.workers.dev/api/comments`; Cloudflare permits this exact origin. Cloudflare-hosted copies use their own same-origin API. Keep the production Worker enabled for GitHub Pages comments to work. To change the generated assets, run `npm ci && npm run build` and commit the results.

This project was made by a human and AI. Feel free to use or modify any part of this code.

## Cloudflare Workers

`wrangler.jsonc` configures the `elon-tuskoff-github-io` Worker with static assets and a shared comments API. `worker/index.js` is the Worker entry point; the browser's `index.js` remains a static asset. Wrangler runs `npm test` and `npm run build` automatically, which also assembles the public site in `dist/`. Only browser files are copied; Worker source, tests, source artwork, build scripts, dependencies, and repository metadata are excluded from public assets.

```sh
npm run deploy:check  # Build and validate the deployment without publishing
npm run deploy       # Publish using your Cloudflare account
```

For the connected Cloudflare Workers Builds project, use `npx wrangler deploy` as the deploy command. The dashboard build command can be left empty because Wrangler's custom build command runs tests and builds the site. If the dashboard already runs `npm run build`, it is safe but duplicates the build. Keep `Test-4` as the production branch. Website updates are committed directly to it. The generated `dist/` and local Wrangler state are ignored by Git.
